# 给程序签名：去掉「未知发布者」提示

> 适用对象：本仓库打出来的免安装包（release 里的 ZhihuishuAuto-<版本>-portable.exe，以及 portable.zip 里解压出来的 ZhihuishuAuto.exe）。
> 相关配置：electron-builder.yml 的 win 段。签名由 electron-builder 调 Windows SDK 的 signtool.exe 完成。

---

## 0. 先分清弹的是哪个窗

| 现象 | 什么时候出现 | 签名能解决吗 |
| --- | --- | --- |
| 「Windows 已保护你的电脑」/「未知发布者」（SmartScreen 蓝色窗口） | 文件带「来自 Internet」标记（从网盘、微信、浏览器下载）且发布者信誉不足 | 能，但需要证书有 SmartScreen 信誉；自签名只能让自己机器安静 |
| 右键属性 → 数字签名 里什么都没有 | 没签名 | 能（签上就有发布者名） |
| 「你要允许此应用对你的设备进行更改吗？」UAC 且发布者显示「未知」 | 程序请求管理员权限 | 本项目是 asInvoker，正常不提权；以后改 requireAdministrator 才会遇到 |
| 杀毒软件报毒 / 拦截 | 启发式误报 | 签名 + 提交误报申诉有帮助，但根治靠白名单 |

本项目现状：未签名，README 里写的是「点更多信息 → 仍要运行」。

---

## 1. 四种方案怎么选

| 方案 | 成本 | 证书要求 | 效果 |
| --- | --- | --- | --- |
| A. 自签名证书 | 0 元 | 自己生成 | 只对导入了这张证书的机器有效（自己电脑、团队内网机器）；别人机器仍显示未知发布者 |
| B. OV 代码签名证书 | 约 1000–3000 元/年 | 企业或个体工商户资质；私钥必须在硬件令牌/HSM 里（2023-06 起 CA/B 论坛强制） | 目标机器能看到公司名；SmartScreen 信誉靠下载量慢慢积累（几天到几周） |
| C. EV 代码签名证书 | 约 3000–6000 元/年 | 同上，审核更严 | 拿证即有较好信誉，通常很快不再弹 SmartScreen |
| D. Azure Trusted Signing（微软云签名） | 约 70 元/月（9.99 美元） | 微软审核，通常要求公司注册满 3 年 | 云签名，无需硬件令牌；信誉同 OV 级别 |

只给自己用：方案 A 就够，最简单。要发给别人：只有 B/C/D 能真正减少弹窗。

---

## 2. 方案 A：自签名证书（推荐先用这个）

以下命令在普通 PowerShell 里执行；导入到「本地计算机 → 受信任的根证书颁发机构」那一步需要管理员。

### 2.1 生成一张代码签名证书

~~~powershell
New-Item -ItemType Directory -Force build\certs | Out-Null
$cert = New-SelfSignedCertificate -Type CodeSigningCert -Subject "CN=ZhihuishuAuto Dev, O=Local" -KeyUsage DigitalSignature -KeyAlgorithm RSA -KeyLength 3072 -HashAlgorithm SHA256 -FriendlyName "ZhihuishuAuto 自签名" -CertStoreLocation "Cert:\CurrentUser\My" -NotAfter (Get-Date).AddYears(5)
$cert.Thumbprint
~~~

### 2.2 导出 pfx（签名用）和 cer（给别的机器导入信任用）

~~~powershell
$pwd = ConvertTo-SecureString -String "换成你自己的密码" -Force -AsPlainText
Export-PfxCertificate -Cert $cert -FilePath build\certs\zhs-selfsigned.pfx -Password $pwd
Export-Certificate -Cert $cert -FilePath build\certs\zhs-selfsigned.cer
~~~

build/certs 下的 *.pfx 别提交到 git（私钥在里面）；*.cer 可以发给团队。

### 2.3 让这台电脑信任这张证书

只导入「个人」还不够，Windows 要把它当根证书：

~~~powershell
# 管理员 PowerShell
Import-Certificate -FilePath build\certs\zhs-selfsigned.cer -CertStoreLocation Cert:\LocalMachine\Root
~~~

图形界面等价操作：certlm.msc → 受信任的根证书颁发机构 → 导入。

### 2.4 手动签一个 exe（验证整条链路）

~~~powershell
# signtool 来自 Windows SDK，路径里的版本号按自己机器改
$signtool = "C:\Program Files (x86)\Windows Kits\10\bin\10.0.22621.0\x64\signtool.exe"
if (-not (Test-Path $signtool)) { Get-ChildItem "C:\Program Files (x86)\Windows Kits\10\bin" -Directory | Select-Object Name }

& $signtool sign /fd sha256 /f build\certs\zhs-selfsigned.pfx /p "换成你自己的密码" /tr http://timestamp.digicert.com /td sha256 release\win-unpacked\ZhihuishuAuto.exe
& $signtool verify /pa /v release\win-unpacked\ZhihuishuAuto.exe
Get-AuthenticodeSignature release\win-unpacked\ZhihuishuAuto.exe | Format-List
~~~

Get-AuthenticodeSignature 的 Status 应为 Valid。

### 2.5 交给 electron-builder 自动签（打包时顺手签）

方式一：环境变量（推荐，密码不进仓库）

~~~powershell
$env:CSC_LINK = "D:\Projects\MultiProject\zhihuishu-auto\build\certs\zhs-selfsigned.pfx"
$env:CSC_KEY_PASSWORD = "换成你自己的密码"
npm run dist
~~~

也认 WIN_CSC_LINK / WIN_CSC_KEY_PASSWORD；CSC_LINK 还可以直接给 pfx 的 base64。

方式二：写进 electron-builder.yml（密码仍建议走环境变量）

~~~yaml
win:
  signtoolOptions:
    certificateFile: build/certs/zhs-selfsigned.pfx
    certificatePassword: ""          # 留空则读 CSC_KEY_PASSWORD / WIN_CSC_KEY_PASSWORD
    signingHashAlgorithms: [sha256]
    rfc3161TimeStampServer: http://timestamp.digicert.com
~~~

签哪些文件：electron-builder 会签两处——

1. win-unpacked\ZhihuishuAuto.exe（构造 app 时，电子构建器的 signApp 流程）；
2. -portable.exe 启动器（生成 NSIS 产物后 signIf(installerPath)，portable 与安装包共用这条路径）。

所以 portable.zip 里解出来的 exe 也已经是签过名的，不用重签。resources\browsers\ 下的 Playwright 组件不经过签名流程（它们不需要被双击，不影响主程序显示发布者）。

## 3. 方案 B：OV 代码签名证书（要发给别人时）

- 购买渠道：DigiCert / Sectigo / SSL.com / GlobalSign 或国内代理商。需要企业营业执照或个体工商户资质；个人身份一般只能买「个人代码签名」（部分 CA 已停售）。
- 2023-06 起 CA/B 论坛规定：OV/EV 私钥必须存放在 FIPS 140-2 Level 2 以上的硬件令牌（YubiKey FIPS、SafeNet eToken 等）或云 HSM。CA 会寄一个类似 U 盘的令牌，签名时插上。
- 用令牌签名（证书在「个人」存储区，令牌已插入）：

~~~powershell
$signtool = "C:\Program Files (x86)\Windows Kits\10\bin\10.0.22621.0\x64\signtool.exe"
& $signtool sign /fd sha256 /sha1 证书指纹 /tr http://timestamp.digicert.com /td sha256 release\win-unpacked\ZhihuishuAuto.exe
~~~

- 交给 electron-builder：用 certificateSubjectName（按证书 Subject 选）或 certificateSha1（按指纹选）：

~~~yaml
win:
  signtoolOptions:
    certificateSubjectName: "你的公司名"
    signingHashAlgorithms: [sha256]
    rfc3161TimeStampServer: http://timestamp.digicert.com
~~~

- 自签名与 OV 的差别只在「别人机器信不信这张证书」，签名命令与配置完全一样。
- SmartScreen 信誉：同一张证书签的 exe 随下载量/运行量积累；换证书会重新开始。所以别频繁换证书、别频繁改包名。

---

## 4. 方案 C：EV 代码签名证书

流程和 OV 一样（硬件令牌 + signtool），审核更严、价格更高；好处是证书一到位就有较好的 SmartScreen 信誉，适合公开分发。

---

## 5. 方案 D：Azure Trusted Signing（微软云签名）

不需要硬件令牌，私钥在微软云 HSM 里，按月计费。需要 Azure 订阅并通过微软企业审核（一般要求公司注册满 3 年，个人开发者不一定过）。

~~~yaml
win:
  azureSignOptions:
    publisherName: "你的公司名"
    endpoint: https://eus.codesigning.azure.net
    codeSigningAccountName: your-signing-account
    certificateProfileName: your-cert-profile
~~~

认证走环境变量（AZURE_TENANT_ID / AZURE_CLIENT_ID / AZURE_CLIENT_SECRET 等），详见微软文档。

## 6. 本项目的落地步骤（自签名，10 分钟）

~~~powershell
cd D:\Projects\MultiProject\zhihuishu-auto

# 1) 生成并导出证书（见 2.1 / 2.2）
# 2) 管理员 PowerShell 导入受信任根（见 2.3）
# 3) 设置环境变量后重新打包
$env:CSC_LINK = "$PWD\build\certs\zhs-selfsigned.pfx"
$env:CSC_KEY_PASSWORD = "换成你自己的密码"
npm run dist

# 4) 验证两个产物
Get-AuthenticodeSignature release\win-unpacked\ZhihuishuAuto.exe | Format-List Status,StatusMessage,SignerCertificate
Get-AuthenticodeSignature release\ZhihuishuAuto-0.1.0-portable.exe | Format-List Status,StatusMessage,SignerCertificate
~~~

两个都应是 Valid，且 SignerCertificate.Subject 里能看到 CN=ZhihuishuAuto Dev。

注意：签名会改变文件字节。签完之后不要再手工修改 exe，否则签名失效。

## 7. 常见坑

1. signtool 找不到：它在 Windows SDK 里，路径形如 C:\Program Files (x86)\Windows Kits\10\bin\<版本>\x64\signtool.exe；装 Visual Studio 的「Windows 10/11 SDK」组件或 winget install Microsoft.WindowsSDK。
2. 时间戳服务器连不上：http://timestamp.digicert.com 偶尔慢，可换 http://timestamp.sectigo.com 或 http://timestamp.acs.microsoft.com。没有时间戳的签名在证书过期后失效。
3. 密码里有特殊字符：PowerShell 里用单引号包住 -p 后面的参数，别让 $ 和 ! 被解释。
4. electron-builder 报找不到证书：确认 CSC_LINK 是 pfx 的绝对路径（或 base64），CSC_KEY_PASSWORD 与导出时一致。构建日志里搜 signing 看它实际调用的命令。
5. 构建缓存导致没重签：win-unpacked 的 exe 有构建缓存（node_modules\.cache\electron-builder），改签名配置后如果 exe 没变化，删掉 release\win-unpacked 和该缓存再打。
6. 自签名后别人机器仍提示：正常，对方没导入你的根证书。要真正消除只能走 OV/EV/云签名。
7. 签名后杀软仍拦截：到 Microsoft / 360 / 火绒的误报上报入口提交；另外别用 UPX 之类加壳。
